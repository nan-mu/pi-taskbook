# 实现与取证

按已确认的设计完成一个可验证的纵向切片。修复任务使用核查阶段的失败信号。若根因仍未判定，先排列少数可证伪的假设，再加能区分假设的最小观测。新功能使用任务书指定的公开入口做冒烟或先跑一个能表明行为缺失的检查。确认检查因要求的行为失败后，做最小修改令它通过，随后在保持行为的前提下整理实现。逐个扩展到任务书要求的其余行为。新增持久测试遵守任务书和仓库规定。

在真实交付物上运行验收。例如验证发布包时，解包后走消费端入口。验证给定命令时，从相同工作目录使用实际入口。记录原状态、交付状态和实际得到的证据。如果基线或者验收方法被新证据推翻，记录冲突并阻塞。

使用任务分支。保留已有的非任务改动。提交任务范围内的变更并提供待审 Git 提交、验证入口和结果。完成本地交付即提交这一阶段的证据。外部推送、开 PR 和发布动作由任务书授权后的交接流程处理。
