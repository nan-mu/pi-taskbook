# 项目事实与术语

任务书的 Goal 描述要达成的状态，Facts 给出适用版本上的依据。读取当前项目的有效事实和术语，先认清对象、术语、适用范围、基线、来源。术语用已有项目语言；定义写清包含什么、排除什么、别名或易混对象。词义随范围变化时分别注明。任务书要求引入、替换或退役一个事实/术语时，核实对应的 Project memory 操作或 Facts 明确创建标记及授权原文，逐项以证据支持适用范围和变更。目标对未来行为的授权不推翻旧基线上的事实。

独立事实审核对每个 M 项核对明确授权、预期旧版本、主张/定义或退役理由、实际证据。授权的替换和退役按既有版本审核；发现超出授权的矛盾则提交 fact-conflict，将项目事实 ID 和新观测交给用户。缺少对应证据就补证。通过复核后，插件在当前分支提交 .fact 的事实历史和术语清单管理区。按本轮同一 .fact 版本核对事实、术语及冲突。工作会话记录的临时推断和未来验收步骤均不能自行升级为项目事实。

若运行数据 evidence.classifyFactChecks 为 true，每个通过的 P 项都要在其 JSON 检查结果中给出 memoryUse。对可在该次观测提交上独立成立、后续设计和规格审核仍需采用的事实，写 "independent"。对用于证明某个 M 项旧状态、退役理由、被替代定义的材料，写 "change-evidence"，在 reason 中列出对应 M 编号和用途。逐项比对适用范围，混在一次核查里的独立观察仍可保留。例如 P1 证实命令的退出码、P2 摘录待退役的旧术语定义、M1 授权退役该术语，P1 应为 independent，P2 应为 change-evidence。任何未获授权的相互矛盾仍须交给用户。重试时已生效的 M 可在任务书原文和项目历史中定位。

evidence.priorProjectFacts 单列已替换、已退役的历史版本。它们解释项目曾经采用或撤回什么；区分现行断言、基线观察和仅用于证明旧状态的材料。对照每个新 P 的语义、对象、适用时间及来源，寻找旧断言换词重现。如果当前来源只是旧证据的另一种说法，要求补证；如需恢复已退役条目，要求任务书指明标识和退役版本、提供新的授权。若同一文件、同一摘录确实支持独立的新判断，在 reason 中给出可以区分两者的条件。插件仅能识别同范围、同来源及摘录、空白或句末句号不同的重复观察；其余语义关系由独审者裁定。
