# Reconcile the taskbook's facts

Check the complete authored fact list, including the attachment, against `registeredTopicFacts` and project facts. Match the constrained entity, source version, scope, and effective status before deciding whether two similarly worded records are duplicates, conflicts, or separate facts. Keep the taskbook's wording and explicit operations. The plugin saves the proposed operations and their task label in the run checkpoint. Designer, Implementer and Review consult this view until signed registration.

Resolve destinations in this stage. An explicit creation carries a subject TSV path. For an older creation or plain fact without a path, select the subject file that owns the decision and include its path in `intakeTargets`. For an update, deletion or reuse, look up the supplied row ID, locator, or exact previous wording. When the supplied reference matches several rows, use the taskbook's explicit scope to disambiguate, or report an intake conflict. When only a similar record exists, show the candidate to the user for a decision. An agent-supplied target cannot replace a missing reference. Preserve the authored replacement or retirement reason. A target names an existing incoming item by its taskbook ID.

When a supplied fact duplicates or changes a registered fact without a clear operation, report `intakeConflicts` with its incoming ID and the existing fact's ID, path, and relevant text. Ask the user to choose whether to reuse, update, or create a separate fact. Also flag a missing target, an ambiguous identity, a mismatched scope, or a contradiction. Apply the recorded `intakeDecisions` to their identified facts. Report a pass once every item can be synchronized. An empty fact list can pass.

Use `taskbook_report` with the current attempt and a short conclusion. Finish after the plugin accepts the report.
